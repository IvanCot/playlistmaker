# Playlist Maker

Учебное Android-приложение на Kotlin и Jetpack Compose. Пакет: `com.ivancot.playlistmaker`.

## Реализовано

- Главный экран: синяя верхняя панель и четыре пункта меню на белом фоне.
- `MainScreen`, `SearchScreen`, `SettingsScreen` и `DetailsScreen` связаны через `PlaylistHost`, `NavHost` и `NavHostController`. Маршруты перечислены в `PlaylistScreen`. Экранные и системная кнопки возврата работают через стек навигации.
- Поиск: `BasicTextField`, подсказка «Поиск», запуск по лупе или клавише поиска, индикатор загрузки, результаты в `LazyColumn`, сообщения о пустом результате и ошибке. Очистка отменяет запрос и скрывает клавиатуру. Изменение текста сбрасывает результаты; новый запрос отменяет предыдущий.
- `SearchViewModel` предоставляет `StateFlow<SearchState>` (Initial, Searching, Success, Fail); UI подписан через `collectAsStateWithLifecycle`. Запрос хранится в `SavedStateHandle`, результаты переживают пересоздание Activity во ViewModel. После восстановления процесса запрос сохранён, поиск запускается пользователем заново.
- `TracksRepositoryImpl` фильтрует данные по названию и исполнителю без учёта регистра, удаляет пробелы по краям запроса и форматирует длительность в `mm:ss`.
- Источник — `LocalNetworkClient`: восемь треков The Beatles из задания и имитация сети с `delay(3000)`. Реальных HTTP-запросов нет; разрешение INTERNET не требуется. `NetworkClient` отделяет источник от репозитория для будущей реализации сети.
- Koin запускается в `MyApplication`. `repositoryModule` предоставляет `NetworkClient` и `TracksRepository`, `viewModelModule` — `SearchViewModel`. Activity получает ViewModel через `by viewModel()`; ручной фабрики и методов-сервисов в Application нет.
- По нажатию трека открывается простой экран деталей с названием, исполнителем и длительностью. Объект передаётся в маршруте как URI-кодированный Gson JSON; состояние поиска сохраняется при возврате. Плеер пока не реализован.
- Настройки: шэринг ссылки на репозиторий, письмо разработчику и открытие оферты. Адрес, тема, тело письма и ссылка берутся из `strings.xml` через `stringResource()`.
- Получатель письма: `20072005i@gmail.com`. Отправка письма пользователем происходит в почтовом приложении.
- «Тёмная тема» отображается отключённым переключателем: логика темы не входит в этот этап.
- «Плейлисты» и «Избранное» показывают Toast с названием кнопки; отдельные экраны не входят в текущий этап.
- В `AndroidManifest.xml` остаётся одна `MainActivity`; прежние Activity-заглушки заменены Compose-экранами.
- Системные отступы учитываются; на низком экране меню прокручивается.

Макет: [Figma, главный экран](https://www.figma.com/design/p0tFHLFx0XBI7BijypwVjW/Playlist-Maker?node-id=1-1714).
Вёрстка ориентируется на светлую версию Figma. Точное соответствие отступов, иконок и шрифта необходимо проверить на устройстве; пока используется системный шрифт Android.

## Запуск

1. Открыть корневую папку в Android Studio и выполнить Gradle Sync.
2. Использовать встроенный JDK Android Studio (Java 25) либо JDK 17.
3. Установить Android SDK Platform 37 и Build Tools 36.0.0 через SDK Manager.
4. Запустить конфигурацию `app` на эмуляторе или устройстве с Android 6.0 (API 23) и новее.

Версии: AGP 9.1.1, Gradle 9.3.1, встроенный Kotlin 2.2.10, Compose BOM 2025.08.00, Koin 4.0.4.
AGP 9 использует встроенную поддержку Kotlin, отдельный плагин `org.jetbrains.kotlin.android` не нужен.

Из PowerShell при установленной Java:

```powershell
./gradlew.bat :app:assembleDebug :app:lintDebug :app:testDebugUnitTest :app:assembleDebugAndroidTest
```

При необходимости указать `JAVA_HOME` на JDK, а `ANDROID_HOME` на SDK или задать `sdk.dir` в локальном `local.properties`. Файл `local.properties` не отправляется в Git.

APK создаётся в `app/build/outputs/apk/debug/app-debug.apk`.

## Проверка переходов

Подключить устройство или запустить эмулятор:

```powershell
./gradlew.bat :app:connectedDebugAndroidTest
```

Инструментальные тесты проверяют переходы, возврат, сохранение запроса при пересоздании Activity, его очистку и внешние Intent. Письмо, шэринг и браузер перехватываются Espresso Intents: тесты не отправляют сообщения.
Добавлена проверка цепочки «поиск → результат → детали → возврат → очистка». Unit-тесты проверяют фильтрацию, длительность, трёхсекундную задержку виртуальным временем, пустой ввод, ошибки, отмену, приоритет нового запроса, сохранённый запрос и разрешение графа Koin.

Вручную также проверить на устройстве:

1. Запуск приложения и четыре кнопки главного экрана.
2. Открытие «Поиска» и «Настроек» без Toast, возврат назад.
3. Toast для «Плейлистов» и «Избранного».
4. Поворот экрана и увеличенный системный шрифт: кнопки остаются доступны через прокрутку.
5. Пустой запрос, ввод кириллицы, очистка и восстановление запроса после поворота.
6. Настройки: выбор приложения для шэринга, все поля черновика письма и переход на оферту.
7. При отсутствии почтового клиента или браузера приложение показывает сообщение и не падает.
8. Запрос `Yesterday`: загрузка около трёх секунд, один трек, длительность `02:05`, переход к деталям и возврат к результатам.
9. Запрос `beatles`: восемь треков; неизвестная строка: «Ничего не найдено».
10. Очистка во время загрузки и новый запрос: старые результаты не появляются.

## Git

Главный экран реализован в `feature/sprint-03`, навигация и настройки — в `feature/sprint-04`. Поиск с MVVM и Koin — в `feature/sprint-05`, созданном от локального `main` с предыдущими спринтами.
Удалённый репозиторий: `git@github.com:IvanCot/playlistmaker.git`.
На GitHub предыдущие спринты ещё нужно влить через PR по порядку: `feature/sprint-03`, затем `feature/sprint-04`. Затем создать PR из `feature/sprint-05` в `main`, чтобы его diff содержал только текущий этап. После проверки выполнить merge.
Не добавлять в PR `.idea`, `local.properties`, `.tools`, каталоги сборки или ключи подписи.

Для push ключ должен быть добавлен в SSH-агент (`ssh-add`) и привязан к GitHub. Проверка доступа: `ssh -T git@github.com`. Отправка веток:

```powershell
git push -u origin feature/sprint-05
```

Затем создать PR на GitHub.
